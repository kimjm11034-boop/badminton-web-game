# 전체 선수 모션과 상황 분류

원천 ZIP 11개의 JPEG 24,170장을 전부 열어 자세를 검출했다. 경기·훈련, 단식·복식을 함께 처리한다. 원본 파일의 장면 코드 20개, 촬영 카메라 R1–R8, 프레임 번호를 보존한다. 카메라와 장면 코드는 자료를 찾는 기준이며, 다른 카메라의 프레임을 동시 촬영으로 연결하지 않는다. [모션 실험실](http://localhost:5173/motion-lab/) · [원본 자료의 파일명 구성](https://aihub.or.kr/aihubdata/data/view.do?aihubDataSe=data&currMenu=115&dataSetSn=71611&topMenu=)

## 직접 분류하기

1. **동작 패턴 → 전체 펼치기**에서 대표 자세를 3D로 비교하고 원하는 묶음을 누른다. **묶어 보기 → 원본 장면 코드**에서는 20개 코드를 따로 찾아볼 수 있다.
2. 사례 카드를 누르면 해당 선수의 원본 사진과 3D 관절을 비교할 수 있다. 사진이 여러 장인 사례는 원본 시점별로 멈추거나 보간 재생할 수 있다. **이 사례와 가장 비슷한 동작 보기**는 다른 촬영 구간에서 해당 사례에 가까운 후보를 최대 8개 고른다.
3. **내 상황 분류**에서 적용 대상을 지정하고 직접 상황명을 저장한다. 패턴 전체에 한 번에 이름을 붙이고 개별 사례나 프레임에 더 구체적인 상황명을 붙일 수 있다. **묶어 보기 → 내가 분류한 상황**에서 모아 본다.
4. **분류 내보내기**는 상황명과 대응하는 패턴·사례·프레임 식별자를 JSON으로 저장한다. **전체 3D 관절 데이터 받기**는 게임에서 읽을 수 있는 전체 좌표를 담는다. 두 파일은 같은 식별자를 사용한다. 분류 작업은 사용 중인 브라우저와 접속 주소에 저장된다.

## 추출과 학습

- 매 사진에서 다중 사람 검출을 실행했다. 공식 선수 박스에 대응하는 후보와 다른 사람을 구분하는 분류기를 학습했다. 2022년 8월 4일 촬영분은 학습에서 따로 떼어 평가했다. 공식 2D 관절 라벨을 우선 사용하고, 나머지 후보에는 YOLO Pose 또는 MediaPipe 관절점을 사용한다. 사람이 겹쳐 대응이 모호하면 사례를 나눴다. 선수 후보가 없는 프레임은 다른 크기의 이미지 영역에서 한 차례 더 검사했다. [전체 검출](all_frames.py) · [선수 후보 선별](player_filter.py) · [같은 선수의 프레임 연결](catalog.py)
- 팔·다리 관절 12점에서 골반 중심 3D 관절을 복원한다. 개별 사진에서 추정한 깊이 정보가 있으면 함께 사용한다. 사진의 2D 관절 배치에 맞춰 팔다리 방향을 보정한 뒤 일정한 분절 길이로 사람 모델에 적용한다. [관절 복원](../learned-rig.js)
- 단일 자세와 연속 동작에 대해 별도로 군집을 학습했다. 손목의 높이와 전후 위치, 팔꿈치·무릎 각도, 좌우 발 간격과 높이, 몸통 기울기를 비교한다. 연속 동작에는 처음에서 끝으로 변한 방향, 중간 자세, 움직인 범위도 반영했다. 원본 기술명과 카메라 번호는 군집 학습에 넣지 않았다. 서로 다른 후보 묶음 수를 평가하고, 각 묶음에 가장 가까운 실제 선수 사례를 대표로 골랐다. [패턴 학습 및 가까운 사례 검색](patterns.py) · [실제 묶음 및 평가 지표](../catalog/patterns.json)

## 다운로드 형식

### 이번 처리 결과

| 항목 | 결과 |
| --- | ---: |
| 원본 사진 / 관절을 복원한 사진 | 24,170장 / 24,130장 |
| 선수 자세 / 선수별 사례 | 60,417개 / 25,213개 |
| 연속 동작 | 15,068사례, 18개 패턴 |
| 단일 자세 | 10,145사례, 32개 패턴 |
| 재검출을 거쳐서도 관절이 남지 않은 원본 | 40장 |

전체 자세의 관절 좌표가 유한하고 팔·다리 분절 길이가 일정한지, 발이 가상 바닥을 뚫지 않는지 검사했다. 원본 관절에 같은 카메라로 다시 투영한 평균 오차는 관측한 관절의 세로 범위 대비 4.35%였다. 이 수치는 2D 일치도다. 별도 촬영일의 실루엣 계수는 단일 자세 0.080, 연속 동작 −0.001로, 특히 연속 동작은 이웃한 묶음과 많이 겹친다. 패턴명은 대표 자세를 설명하며 최종 게임 상황은 사용자가 지정한다.

전체 좌표 파일은 gzip으로 압축한 UTF-8 JSON Lines다. 첫 줄에서 관절 배열 순서와 단위를 읽는다. 선수 사례마다 패턴 식별자, 카메라, 장면 코드, 원본 ZIP과 사진 이름, 각 프레임의 22개 관절 좌표, 관절 각도, 추정 무게중심과 양발 접지 후보를 제공한다. 단위는 미터이고 좌표계는 선수의 해부학적 오른쪽·위·뒤쪽이다. 관절을 복원하지 못한 원본 사진도 별도 행에 남긴다. [전체 파일 받기](http://localhost:5173/motion-lab/catalog/motion-library.jsonl.gz) · [출력 및 검증 코드](export-catalog.mjs)

날짜가 같은 근접 이미지 사이에도 촬영 표본이 빠져 있을 수 있다. 보간한 시점은 실험실에서 구분하며 전체 다운로드에는 실제 관측 시점만 싣는다. 선수의 깊이, 실제 코트 이동 거리, 무게중심과 접지는 추정값이다. 자동 군집은 사람이 지정한 게임 상황의 정답을 제공하지 않는다. 같은 원본 장면 안에는 타격 선수와 상대의 반응 자세가 함께 있을 수 있다.

## 재현 순서

프로젝트 루트에서 실행한다. 원천 ZIP, 공식 라벨 ZIP, 이전 단계에서 학습한 3D 모델과 MediaPipe 캐시를 사용한다. 전체 사진용 로컬 검출기는 YOLOv8n Pose의 ONNX 변환본이며 SHA-256은 `04f6d2416266f2aba6c5ba8b26de33ed9eba3279f972ac02e33f9f1366547586`이다. 모델 위치는 `.cache/pose/yolov8n-pose.onnx`다. DirectML을 사용할 때는 PC의 그래픽 어댑터 번호를 지정한다. 로컬에서 다시 학습할 때만 Python, OpenCV, ONNX Runtime, MediaPipe, NumPy, SciPy, scikit-learn이 필요하다. [검출 모델 파일](https://huggingface.co/Xenova/yolov8n-pose/blob/main/onnx/model.onnx) · [기본 모델 학습](REPORT.md)

## 관절 포인트 검수

개발 서버에서 [관절 검수 작업장](http://localhost:5173/motion-lab/review/)을 연다. 모션 실험실의 ‘이 프레임 수정’으로 선택한 선수와 원본 사진을 바로 열 수도 있다. 원본 ZIP 11개의 사진 24,170장을 모두 찾아볼 수 있다. 한 사진에 여러 선수가 있을 수 있다.

| 작업 목록 | 초기 수량 | 검수 대상 |
| --- | ---: | --- |
| 관절 미검출 | 40장 | 자동 복원된 선수가 없는 사진 |
| 관절 위치 검토 후보 | 40,556건 | 가시성, 좌우 불일치, 검출기 간 거리 차이 또는 작은 신체 크기로 표시한 선수 자세 |
| 선수 여부 미확정 | 78,706건 | 기존 선수 목록에 채택되지 않은 사람 검출. 중복, 관중, 심판이 포함될 수 있음 |
| 모든 사례 | 139,163건 | 위 세 목록과 나머지 선수 자세 19,861건. 직접 추가한 선수도 여기에 포함됨 |

선수 기준 좌우로 관절을 선택하고 원본 사진을 클릭한다. 기존 점은 끌어서 옮길 수 있다. 사진에 초점이 있으면 방향키로 1픽셀, Shift와 방향키로 10픽셀씩 이동한다. 점이 없는 선수는 ‘선수 영역 그리기’로 범위를 먼저 정한다. 같은 사진의 다른 선수는 ‘이 사진에 선수 추가’를 사용한다. 근거가 부족한 관절은 ‘애매함’이나 ‘가림’만 표시해도 된다. 양쪽 어깨·팔꿈치·손목·골반·무릎·발목의 위치가 있으면 수정 전후의 3D 추정을 비교할 수 있다.

‘임시 저장’은 작업 중인 사본을 보존한다. ‘검수 제출 · 학습’은 원본 픽셀 좌표, 상태, 선수 범위와 메모를 프로젝트의 `motion-lab/review/annotations/reviews.sqlite`에 저장한다. 다른 창에서 같은 사례를 먼저 저장하면 덮어쓰기 전에 충돌을 알린다. ‘제출 자료 받기’는 최신 제출본을 관절 이름과 함께 JSONL로 내보낸다.

위치 제안 모델은 선수 범위를 4×8칸으로 나눠 밝기와 가로·세로 경계 특징을 구한 뒤, 관절별로 가까운 검수 사례 최대 5개의 정규화된 좌표를 거리 가중 평균한다. 확인한 좌표만 예시로 사용하며 해당 사례 자체는 제안에서 제외한다. 재제출하면 이전 예시를 교체한다. 3D 깊이와 접지는 기존 단안 추정·리그에서 계산한다. 경기 모션 뱅크의 재생성은 별도 단계다.

검수 색인은 `python -X utf8 motion-lab/training/review_sources.py`로 재생성한다. 원본 ZIP과 사용자 제출 데이터는 별도 파일로 보관한다.
